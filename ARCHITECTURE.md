# Architecture

High-level overview of how the portfolio is wired together. Read this if you want to understand the project beyond a tour of the repo. Engineering conventions live in [`CLAUDE.md`](./CLAUDE.md); design tokens in [`src/styles/global.css`](./src/styles/global.css).

## Route map

```
/                      Landing — conversion-ordered funnel
/work                  Index of case studies
/work/[slug]           Individual case study (MDX content collection)
/blog                  Index of blog posts
/blog/[slug]           Individual post (MDX content collection)
/blog/tag/[tag]        Posts filtered by tag (indexable for topical SEO)
/about                 Trust supporter — short, headshot, resume link
/contact               First-class CTA destination — form + email + LinkedIn
/rss.xml               RSS feed (@astrojs/rss)
/sitemap-index.xml     Generated by @astrojs/sitemap
/og/[slug].png         Dynamic OG image generator (Satori)
/api/contact           Astro endpoint → Resend
/api/cron/brief        Vercel cron → Anthropic API → GitHub PR (monthly)
```

## Brief pipeline (monthly cron)

The "Web Dev Brief" is a monthly hybrid AI-research + human-polish digest. The pipeline runs on Vercel cron, produces a draft as a GitHub PR, and waits for human review.

```
┌──────────────────────────┐
│ Vercel cron              │  schedule: "0 9 1 * *" (1st of month, 09:00 UTC)
│ → POST /api/cron/brief   │
└──────────────────────────┘
            │
            ▼
┌──────────────────────────────────────────────────────────┐
│ src/pages/api/cron/brief.ts                              │
│   1. Auth gate: verify Bearer <CRON_SECRET>              │
│   2. Anthropic SDK — research call (Sonnet + web_search) │
│   3. Anthropic SDK — draft call (Sonnet, voice prompt)   │
│   4. Assemble MDX (frontmatter + body)                   │
│   5. Octokit — create branch + commit + open PR          │
│   6. On error → Resend alert email                       │
└──────────────────────────────────────────────────────────┘
            │
            ▼
┌──────────────────────────┐    ┌─────────────────────────┐
│ GitHub PR opened          │ ─→ │ Author polishes ~30 min │
│ (label: automated)        │    │ → squash-merges         │
└──────────────────────────┘    └─────────────────────────┘
                                            │
                                            ▼
                                ┌──────────────────────────┐
                                │ Astro rebuild → live     │
                                └──────────────────────────┘
```

Code path:

- Endpoint: `src/pages/api/cron/brief.ts`
- Orchestration: `src/lib/brief/generate.ts`
- Octokit wrapper: `src/lib/brief/github.ts`
- Versioned prompts: `src/lib/brief/prompts/{research,draft}.md`
- Manual debug runner: `scripts/run-brief.ts`

Required env vars: `ANTHROPIC_API_KEY`, `GITHUB_TOKEN`, `CRON_SECRET`, `RESEND_API_KEY`, `BRIEF_MODEL`, `BRIEF_NOTIFY_EMAIL`.

> Any work on this pipeline must invoke the `claude-api` skill first — bundles current best practices (prompt caching, correct model IDs, tool use, batch, citations).

## Contact flow

```
Form (React island) → POST /api/contact → Zod validate → Resend.emails.send → 200
                                                              │
                                                              └─ to: kristijan.kresic.dev@gmail.com
```

Anti-spam: honeypot field + minimum-time-on-form check. No captcha (friction kills conversion). Per-IP rate limit on the endpoint.

`intent` field (hidden, prefilled from URL `?intent=hire|project`) drives the email subject line:

- `?intent=hire` → `[Hire] <name> from <company>`
- `?intent=project` → `[Project] <name> from <company>`
- fallback → `[Contact] <name>`

## Design system

Tokens live in `src/styles/global.css` (`@theme {}` block — Tailwind v4 native). Spec is in the Obsidian vault at `01 - Projects/portfolio-v2/design-system.md`.

- **Theme:** dark only, no toggle
- **Accent:** amber `#F59E0B` (hover `#FBBF24`, active `#D97706`)
- **Fonts:** Geist (display + body) + Geist Mono
- **Spacing:** 4px base scale
- **Motion:** Framer Motion springs + CSS easings + `prefers-reduced-motion` respected everywhere

## Why Astro?

- Static-first → zero JS on most routes → Lighthouse 95+ by default
- Content Collections give type-safe MDX out of the box
- Islands architecture means motion + form code only hydrate where needed
- View Transitions API built-in (no router lib)
- Adapter abstraction → Vercel deploy is a single integration

Alternatives ruled out: Next.js (overkill — more JS on client by default, RSC complexity unnecessary for static-heavy site). Plain MDX generators (no island model).

## Why amber?

Originally locked molten orange `#FF6B2B` for differentiation. Reconsidered through B2B dev-hiring lens — high-saturation orange triggers "discount/sales" subconscious read. Amber `#F59E0B` keeps warmth + differentiation but reads premium/craft. Single accent throughout the site keeps the brand legible.
