## Route map

```
/                      Landing — conversion-ordered funnel
/work                  Index of case studies
/work/[id]             Individual case study (MDX content collection — the glob loader's param is `id`)
/blog                  Index of blog posts
/blog/[slug]           Individual post (MDX content collection)
/blog/tag/[tag]        Posts filtered by tag (indexable for topical SEO)
/about                 Trust supporter — short, headshot, resume link
/contact               First-class CTA destination — form + email + LinkedIn
/cv                    Redirect → /cv/kristijan-kresic-cv.pdf (committed render from cv/; linked from nav, footer, About, Contact hire-card)
/rss.xml               RSS feed (@astrojs/rss) — single feed URL
/sitemap-index.xml     Generated by @astrojs/sitemap
/og/[slug].png         Dynamic OG image generator (Satori)
/_actions/contact      Astro Action (contact form) → Resend
```

The landing page shows featured content only (3 case studies, 3 latest Briefs); `/work` and `/blog` are the full indexes. Both ship **unpaginated** — a single grid/list. Add Astro's `paginate()` only when either collection passes ~20 entries; a paginated route with 3 posts reads worse than none. (Decided 2026-07-17.)

The Brief pipeline has no route — it runs as a **scheduled GitHub Action** (`.github/workflows/brief.yml`, monthly), not a Vercel cron. See "Brief pipeline" below.

A `<FeaturedWriting />` section (3 latest Briefs) belongs to the target landing above, but was never built — the blog was cut from launch 2026-07-17 and lands in Phase 6.

All sections are static Astro components. Motion is progressive enhancement via the vanilla `motion` package (`animate` / `inView`) in plain `<script>` tags, or CSS scroll-driven animations — **no client framework ships**. Reveals are fast (≤400ms), animate content in without gating it, and respect `prefers-reduced-motion`.

## Brief pipeline (monthly, scheduled GitHub Action)

The "Web Dev Brief" is a monthly hybrid AI-research + human-polish digest. The pipeline runs as a **scheduled GitHub Action** (post-launch, Phase 6), produces a draft as a GitHub PR, and waits for human review. (Originally specced as a Vercel cron + public endpoint; moved to Actions 2026-07-17 — built-in `GITHUB_TOKEN` instead of a fine-grained PAT that expires silently, no public endpoint or `CRON_SECRET` to secure, no serverless duration cap, logs in Actions, and the script runs locally for debugging.)

```
┌──────────────────────────────┐
│ .github/workflows/brief.yml  │  schedule: "0 9 1 * *" (1st of month, 09:00 UTC)
│ → runs scripts/brief.ts      │
└──────────────────────────────┘
            │
            ▼
┌──────────────────────────────────────────────────────────┐
│ scripts/brief.ts (orchestrates src/lib/brief/*)          │
│   1. Anthropic SDK — research call (web_search tool)     │
│   2. Anthropic SDK — draft call (voice prompt)           │
│   3. Assemble MDX (frontmatter + body)                   │
│   4. Octokit — create branch + commit + open PR          │
│      (built-in GITHUB_TOKEN inside Actions)              │
│   5. On error → Resend alert email                       │
└──────────────────────────────────────────────────────────┘
            │
            ▼
┌──────────────────────────┐    ┌─────────────────────────┐
│ GitHub PR opened          │ ─→ │ Author polishes ~30 min │
│ (label: automated)        │    │ → squash-merges         │
└──────────────────────────┘    └─────────────────────────┘
                                            │
                                            ▼
                                ┌──────────────────────────┐
                                │ Astro rebuild → live     │
                                └──────────────────────────┘
```

Code path:

- Runner: `scripts/brief.ts` (same entry point in the Action and locally)
- Orchestration: `src/lib/brief/generate.ts`
- Octokit wrapper: `src/lib/brief/github.ts`
- Versioned prompts: `src/lib/brief/prompts/{research,draft}.md`

Required secrets (GitHub Actions): `ANTHROPIC_API_KEY`, `RESEND_API_KEY` (+ optional `BRIEF_MODEL`, `BRIEF_NOTIFY_EMAIL` vars). `GITHUB_TOKEN` is the Action's built-in token; a PAT is only needed for local runs.

> Any work on this pipeline must invoke the `claude-api` skill first — bundles current best practices (prompt caching, correct model IDs, tool use, batch, citations).

## Contact flow

```
HTML form (progressive enhancement) → Astro Action `contact` → Zod validate → Resend.emails.send → 200
   (src/actions/index.ts, accept: 'form')                            │
                                                                     └─ to: kristijan.kresic.dev@gmail.com
```

Astro Actions replace the originally-specced hand-rolled `/api/contact` endpoint (2026-07-17): Zod input validation, typed errors (`ActionError`), and HTML-form fallback come built in — no client/server schema mirroring, no manual `fetch`. The action route still runs server-side on Vercel (Actions are on-demand by nature).

Anti-spam: honeypot field + minimum-time-on-form check. No captcha (friction kills conversion). No per-IP rate limiting in v1 — in-memory counters are meaningless on serverless (fresh instance per invocation); add Turnstile invisible or Upstash only if real spam shows up.

`intent` field (hidden, prefilled from URL `?intent=hire|project`) drives the email subject line:

- `?intent=hire` → `[Hire] <name> from <company>`
- `?intent=project` → `[Project] <name> from <company>`
- fallback → `[Contact] <name>`

## Design system

Tokens live in `src/styles/global.css` (`@theme {}` block — Tailwind v4 native). Spec is in the Obsidian vault at `01 - Projects/portfolio-v2/design-system.md`.

- **Theme:** dark only, no toggle
- **Accent:** amber `#F59E0B` (hover `#FBBF24`, active `#D97706`)
- **Fonts:** Geist (display + body) + Geist Mono
- **Spacing:** 4px base scale
- **Motion:** vanilla Motion springs + CSS easings + `prefers-reduced-motion` respected everywhere. Conversion-first budget: fast content-revealing animations (≤400ms), no scroll hijacking, no smooth-scroll library

## Why Astro?

- Static-first → zero JS on most routes → Lighthouse 95+ by default
- Content Collections give type-safe MDX out of the box
- Astro Actions give a typed, validated form backend without endpoint boilerplate
- Native cross-document view transitions (CSS `@view-transition`) — no router lib, no `<ClientRouter />` JS (Baseline 2026)
- Adapter abstraction → Vercel deploy is a single integration

Alternatives ruled out: Next.js (overkill — more JS on client by default, RSC complexity unnecessary for static-heavy site). Plain MDX generators (no island model).

## Why amber?

Originally locked molten orange `#FF6B2B` for differentiation. Reconsidered through B2B dev-hiring lens — high-saturation orange triggers "discount/sales" subconscious read. Amber `#F59E0B` keeps warmth + differentiation but reads premium/craft. Single accent throughout the site keeps the brand legible.
