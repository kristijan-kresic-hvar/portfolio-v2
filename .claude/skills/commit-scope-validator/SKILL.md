# commit-scope-validator

Pre-flight check for Conventional Commit messages in this repo. Reads `commitlint.config.js` and exposes the locked whitelists so commit attempts never fail at the commit-msg hook for an invalid scope.

## Why this exists

`lefthook.yml` runs `commitlint` as a `commit-msg` hook. Lefthook fails commits with an invalid type or scope, which:

- Wastes a round-trip (Claude proposes message → hook rejects → revise → retry)
- Encourages workarounds (`--no-verify`) that bypass the gate the project actually wants enforced
- Loses the commit message draft in some terminals

The fix: surface the whitelists into context _before_ the commit happens.

## What the skill does

1. Read `commitlint.config.js` at repo root.
2. Extract the `type-enum` and `scope-enum` arrays.
3. Surface them in Claude's context as a quick-reference block.
4. If Claude is about to call `git commit -m "<message>"`, validate the message format first:
   - Type matches `<one of type-enum>` exactly
   - Scope (if present) matches `<one of scope-enum>` exactly
   - Subject is lower-case OR sentence-case OR start-case
   - Subject ≤72 characters
   - Body lines ≤100 characters

If validation fails, propose a corrected message before running `git commit`.

## Format reminder

```
<type>(<scope>): <imperative description ≤72 chars>

<optional body — explain WHY, not what. Wrap at 100 chars.>
```

## Banned in commit messages (per CLAUDE.md)

- ❌ `Co-Authored-By:` trailers
- ❌ `🤖 Generated with Claude Code` footers
- ❌ HEREDOC `$(cat <<'EOF' ... EOF)` wrapping
- ❌ "Generated by AI" / "Assisted by" boilerplate
- ❌ The word "and" in subject — atomicity rule: split the commit instead

## When to invoke

- Before any `git commit -m ...` command
- When the user asks "what scope should I use for X?"
- When CLAUDE.md or dev-conventions.md `commit-scope` is mentioned

## What this skill does NOT do

- Does not modify `commitlint.config.js` — that's the source of truth
- Does not run `git commit` directly — it validates the message, the user / parent agent runs the commit
- Does not bypass lefthook — it complements the gate by removing failures
- Does not propose new scopes — additions go through PR review against the whitelist
